The declaration every recipe checks

The law refuses this flow twice, once for each way back it lacks.

// payments.zayn
DEFINE INTENT_FLOW approve_payment (
  SATISFIES [SELECT, CONFIRM, ACT]
)

In words: a payment the user approves, with nothing reachable: the user acts and can neither leave nor take it back.

$ zayn check payments.zayn
payments.zayn:2  error  MISSING_UNDO  approve_payment
    An act declares no way back: SATISFIES holds ACT, ALWAYS_REACHABLE lacks UNDO.
    Rule 79 · The Undo Covenant · Article IV · the right to reverse
payments.zayn:2  error  MISSING_CANCEL  approve_payment
    A flow that acts cannot be abandoned: ALWAYS_REACHABLE lacks CANCEL.
    Rule 26 · The Back Button is Holy · Article IV · the right to leave

2 error(s), 0 warning(s) across 1 file(s) at level 2

A program reads two things: the exit code, 0 when lawful and 1 when refused, and with --json the report, field by field ↗.

A shell

if zayn check payments.zayn > /dev/null; then
  echo "lawful"
else
  echo "refused (exit $?)"
fi

In words: the shell hides the report and branches on whether the command succeeded.

$ sh check.sh
refused (exit 1)

Python

import json, subprocess

run = subprocess.run(["zayn", "check", "payments.zayn", "--json"], capture_output=True, text=True)
for d in json.loads(run.stdout)["diagnostics"]:
    print(d["code"], d["cites"][0], "line", d["span"]["line"])
print("exit", run.returncode)

In words: Python loads the JSON and prints each refusal with its rule and line, then the code the command returned.

$ python check.py
MISSING_UNDO rule:79 line 2
MISSING_CANCEL rule:26 line 2
exit 1

JavaScript

const { spawnSync } = require('child_process');

const run = spawnSync('zayn', ['check', 'payments.zayn', '--json'], { encoding: 'utf8' });
for (const d of JSON.parse(run.stdout).diagnostics) console.log(d.code, d.cites[0], 'line', d.span.line);
console.log('exit', run.status);

In words: the same lines from JavaScript, through its module for child processes.

$ node check.js
MISSING_UNDO rule:79 line 2
MISSING_CANCEL rule:26 line 2
exit 1

Go

package main

import (
	"encoding/json"
	"errors"
	"fmt"
	"os/exec"
)

type report struct {
	Diagnostics []struct {
		Code  string
		Cites []string
		Span  struct{ Line int }
	}
}

func main() {
	out, err := exec.Command("zayn", "check", "payments.zayn", "--json").Output()
	code := 0
	var exit *exec.ExitError
	if errors.As(err, &exit) {
		code = exit.ExitCode()
	}
	var r report
	json.Unmarshal(out, &r)
	for _, d := range r.Diagnostics {
		fmt.Println(d.Code, d.Cites[0], "line", d.Span.Line)
	}
	fmt.Println("exit", code)
}

In words: Go fills a typed structure, whose fields match the JSON by name, and prints the same lines.

$ go run check.go
MISSING_UNDO rule:79 line 2
MISSING_CANCEL rule:26 line 2
exit 1

PowerShell

$json = zayn check payments.zayn --json
$code = $LASTEXITCODE
$report = ($json -join "`n") | ConvertFrom-Json
foreach ($d in $report.diagnostics) { Write-Output "$($d.code) $($d.cites[0]) line $($d.span.line)" }
Write-Output "exit $code"

In words: PowerShell saves $LASTEXITCODE first, since the next command replaces it, then prints the same lines.

$ powershell -NoProfile -ExecutionPolicy Bypass -File check.ps1
MISSING_UNDO rule:79 line 2
MISSING_CANCEL rule:26 line 2
exit 1

This page is a Zayn surface: its visitor comes to locate their language, read its recipe and compare it with the others.

// calling.zayn
DEFINE SCREEN calling (
  SATISFIES [LOCATE, READ, COMPARE],
  ALWAYS_REACHABLE [EXIT]

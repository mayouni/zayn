# zayn 0.2.0

The release of `zayn`, the Zayn verifier and its local server, under its name: one file for each system, and one WebAssembly
module for a browser. The commit it is built from is the one the tag `v0.2.0` names, so these notes do not name it. It follows
`zane 0.1.0` (`doc/releases/v0.1.0.md`): the same command, renamed, with the law, the language and the site of today.

`zayn --version` prints `zayn 0.2.0`. It names no commit, because the tag does.

- **The law:** v3.17. **The language:** 1.7. **The contract:** v1.11.
- **Conformance:** level 4, 77 fixtures of 77.
- **The compiler:** Zig 0.15.2. Every file is `ReleaseSmall`. Linux is musl and statically linked.

## The files are not signed

No file carries a signature. Windows SmartScreen may warn before it runs `zayn-0.2.0-x86_64-windows.exe`. macOS will refuse
to open a file downloaded from the web until its quarantine is removed. The hash is how to know a file is the one built
here. Compare it with the line for that file in `SHA256SUMS` and in the table above.

**On Windows** (PowerShell), in the folder that holds the file:

```powershell
Get-FileHash .\zayn-0.2.0-x86_64-windows.exe -Algorithm SHA256
```

The hash it prints, in capitals, is the same as the one in `SHA256SUMS`. `certutil -hashfile zayn-0.2.0-x86_64-windows.exe SHA256`
prints it too.

**On Linux**, with `SHA256SUMS` beside the file:

```bash
sha256sum -c SHA256SUMS --ignore-missing
chmod +x zayn-0.2.0-x86_64-linux
```

**On macOS**, with `SHA256SUMS` beside the file:

```bash
shasum -a 256 -c SHA256SUMS --ignore-missing
chmod +x zayn-0.2.0-aarch64-macos
xattr -d com.apple.quarantine zayn-0.2.0-aarch64-macos
```

Each file you have prints `OK`. A file that prints `FAILED` is not the one built here: do not run it.

## Building it yourself

With Zig 0.15.2, from a clone at the tag `v0.2.0`:

```bash
zig build -j2 release
```

`zig-out/release/SHA256SUMS` is then the same as the one published.
